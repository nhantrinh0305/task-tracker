# Task Tracker

A simple command-line task tracker built with JavaScript and Node.js. Add, update, delete, and organize tasks by status. Tasks are saved locally in `tasks.json`.

## Getting started

Install Node.js, then open a terminal in the `task-tracker` folder. No external packages or `npm install` are needed.

```sh
node --version
node task-tracker.js list
```

Run commands from this folder because the program reads and writes `tasks.json` in the terminal's current working directory.

## Commands

| Action | Command |
| --- | --- |
| Add a task | `node task-tracker.js add "Buy groceries"` |
| Update a description | `node task-tracker.js update 1 "Buy groceries and cook dinner"` |
| Delete a task | `node task-tracker.js delete 1` |
| Start a task | `node task-tracker.js mark in-progress 1` |
| Complete a task | `node task-tracker.js mark done 1` |
| Move a task back to todo | `node task-tracker.js mark todo 1` |
| List all tasks | `node task-tracker.js list` |
| List todo tasks | `node task-tracker.js list todo` |
| List tasks in progress | `node task-tracker.js list in-progress` |
| List completed tasks | `node task-tracker.js list done` |

Replace `1` with the ID printed when you add a task. Put descriptions in quotes when they contain spaces.

### Statuses

- `todo`: the default for new tasks.
- `in-progress`: tasks you are working on.
- `done`: completed tasks.

Tasks can move between any of these statuses. Both `mark` and `list` accept `to-do` as an alias for `todo`; the stored value is always `todo`.

### List output

`list` displays each description with its status, for example:

```text
Buy groceries (todo)
Learn JavaScript (in-progress)
Write a report (done)
```

`list in-progress` displays only matching descriptions:

```text
Learn JavaScript
```

List output does not include IDs. You can also look up IDs in `tasks.json`.

When there are no tasks, the program prints `No tasks found.` A filter with no matches prints a message such as `No tasks found with status: done.`

## Data storage

The first successful `add` creates `tasks.json` if it does not exist. Each task has this structure:

```json
{
  "id": 1,
  "description": "Buy groceries",
  "status": "todo",
  "createdAt": "2026-10-13T07:23:05.151Z",
  "updatedAt": "2026-10-13T07:23:05.151Z"
}
```

The file stores an array of task objects. IDs are generated by adding one to the highest existing ID, so deleting the highest ID can allow it to be reused. Updating a description or marking a status refreshes `updatedAt`, while `createdAt` stays unchanged. Marking the current status again also refreshes `updatedAt`.

`tasks.json` is excluded from Git by `.gitignore`.

## Input validation

- IDs must be positive safe integers.
- Descriptions cannot be empty or contain only whitespace. Surrounding whitespace is trimmed.
- Statuses and commands must match the lowercase names shown above.
- Invalid arguments display a usage message.
- Updating, deleting, or marking an unknown ID displays `404: Task not found (ID: ...)`.

Errors are printed to the terminal and set the process exit code to `1`.
